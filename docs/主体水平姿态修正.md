# 主体水平姿态修正（2026-10-28）

> **尺寸定义已进一步校正：**用户明确 135 mm 是两个实物电机轴心中点到轮心的侧视直线距离，非单关节竖直高度。本页后续 135 mm 垂距、193 mm 髋高与旧训练目录均为历史记录。最新站姿、尺寸与命令见 [135毫米中点距离校正](135毫米中点距离校正.md)。

用户确认：正常站立时主体安装面应与地面平行。此前程序把 CAD 根坐标 z 当作主体法向，导致初始模型本身斜立，首轮与原第二轮训练目标不符合这一要求。此前报告的约 13.7° 是相对旧坐标系的偏差，不是主体安装面与地面的夹角；旧评估的存活率不能证明站姿正确。

## 已修正

- 从 base 内实际安装板 `part_151_solid_151` 的网格平面求法向，使用另外两块平行结构件验证方向一致。方向不再依赖 CAD 根坐标 z。
- 对整个机器人根姿态施加旋转，几何、各刚体质量与惯性、内部关节及闭链关系不变。
- 用物理主体坐标计算角速度、重力观测、姿态奖励与跌倒判断。
- 默认配置和第二轮配置均启用该安装板参考；旧 checkpoint 自带的配置缺少该字段，仍按旧逻辑回放，避免悄悄改变其观测含义。
- 原 135 mm 髋轮垂距在正确姿态下可闭合，主体几何净空约 25.6 mm；旧 320 mm 的选择源于错误根姿态，已撤销。髋部目标世界高度约 193 mm。
- 姿态奖励改为以 5° 为尺度的指数奖励；持续倾斜不能再获得接近水平的姿态奖励。
- 38 项测试通过，两个配置各 2000 步零/随机动作 smoke 通过；这是初始化、数值与接口检查，不是新策略已训练成功。

原第二轮运行 `cad_dynamics_standing_round2_20261028` 已在 500,000 步发出 SIGINT，代码保存了 `interrupted_policy.zip`，状态文件中的 `KeyboardInterrupt` 对应本次主动停止。旧 checkpoint 与原始 CAD 导出保留。新物理姿态、观测参考与模型快照不同，禁止直接 warm-start 旧策略，应从零重新训练。

## 查看正确初始姿态

这条命令只展示模型姿态，不施加策略或推进动力学，不应当作已学会站立：

```bash
MUJOCO_GL=glfw OMP_NUM_THREADS=1 \
/root/gpufree-data/.venvs/climber-validation/bin/python scripts/play.py \
  --config configs/robot/cad_dynamics.yaml --pose-only
```
