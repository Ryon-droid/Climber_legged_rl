## 为什么不继续原配置叠步数

完整趴姿动作轨迹显示：机器人基本保持腹部落地，腿长仍约 0.38–0.39 m，远未达到 0.135 m 目标；气弹簧由初态约 217.8 mm 到达约 220 mm 上止挡。最大可见微小越界约 0.31 mm，是模型软限位的数值柔性。

与第四轮不同，本轮没有持续触及电机限幅：独立趴姿评估中各电机 99% 限幅占比均为零。不能再把本轮直接解释为“全程力矩打满所以起不来”。动作诊断中左右腿输出明显不一致，起身进度和抬升奖励接近零，存活项约 +0.5、未完成项 -0.1；这是几乎不动、等待超时的退化行为。

这说明本轮没有学到有效起身控制，现有奖励与初始化下缺少能带出趴姿的学习信号；并不能单凭这些样本证明硬件无法起身。不能凭空改变 450 N 气弹簧、传动比、质量或电机力矩来制造成功。

上一轮约定 200,000 步仍为零就先验证动态路径，故本次没有生成或启动第六轮长训配置，也不把第五轮原样换个 run-name 当作改进方案。

## 本次动作可行性诊断

在同一模型和现有力矩、速度、闭链、155–220 mm 气弹簧行程、起身倾角包络及最终站稳标准下，做了 12 代四阶段对称动作搜索。搜索分数仅是接近目标的代价，不是成功率。搜索尚未找到成功动作。

新增 `scripts/search_getup_feasibility.py`，把这种诊断做成可重复命令。它搜索每阶段的前腿、后腿和轮部动作，保持四个腿电机独立执行，候选左右动作对称，不在模型中强制关节同步。它不改变根部位置或物理参数，不放宽成功判据；完整起身真正取得后才允许既有策略继续保持站稳。

工程验证：在现有最佳候选初始化下跑了 1 代/24 次目标函数评估，并对后展 0.36、0.37、0.375 m 三种完整趴姿分别执行到真实终止。结果 0/3，全部起身超时，报告 `passed=false`，脚本退出码为 2，按预期报告失败而不是成功。语法编译通过。

记录：评估目录下 `initial_action_search_*` 和 `feasibility_search.json`。搜索仅覆盖有限的对称动作序列，失败不证明其他动态控制也不可能。

## 下一步指令：先搜索可行起身动作

这一步不是 PPO 训练。先获得在完整趴姿能执行的动作，再据此做参考/示教或重新设计奖励，才有依据启动下一轮。该脚本不会自动启动 PPO，也不会修改运行配置。

```bash
cd /root/gpufree-data/Climber_legged_rl
set -o pipefail
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 /root/gpufree-data/.venvs/climber-validation/bin/python -u scripts/search_getup_feasibility.py \
  --config configs/robot/cad_getup_stand_round5_dynamic.yaml \
  --standing-checkpoint outputs/mujoco_runs/cad_getup_stand_round5_dynamic_20261029/best/best_model.zip \
  --iterations 40 --population-size 8 --workers 4 --seed 88 \
  --initial-report outputs/cad_getup_stand_round5_dynamic/assessment_20261029/feasibility_search.json \
  --output outputs/cad_getup_stand_round5_dynamic/assessment_20261029/feasibility_search_extended.json \
  2>&1 | tee outputs/cad_dynamics/cad_getup_feasibility_search_20261029.log
```

结束时看 `passed` 和 `validation_success_count`，不能只看 score 下降。即使通过三种确定性初态，也仍需新种子、扰动和完整时域验证，不能直接认定比赛可用。若仍失败，应进一步检查动态控制路径、实际传动输出、弹簧安装方向及真实力曲线，再确定训练方案。
