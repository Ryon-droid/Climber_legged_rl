## 实际训练结果

使用 `configs/robot/cad_balance_estimator_round14.yaml`，从第十三轮 `best_model.zip` 初始化，4 个并行环境完成 8192 步 PPO 训练。训练和前后评估共 102 秒，不含首次安装与文件传输时间。

- 9 个站立分支权重张量发生更新；起身分支和速度估计器权重保持冻结。
- `final_policy.zip` 保存成功；普通 PPO 和项目自定义 PPO 重新加载后的确定性动作完全一致，最大差为 0。
- 重新加载后额外运行 200 步，观测、奖励均为有限值；回放优化器状态可恢复。
- 独立测试：正常站立 10/10、趴姿起身 10/10；另有混合测试 10/10。这是小样本仿真验证，不能解释为所有动作都已训练完成。
- 训练开始前的固定困难测试仍有失败：困难站立成功率 0.875，困难推扰成功率 0。短测试没有证明这些问题已经解决。
- 40 项现有测试通过，覆盖梯度裁剪、速度估计、站立回放、困难重置、评估调度和电机动作分布；`pip check` 通过。

## 在工作站启动后续训练

重新从经过评估的第十三轮父策略开始第十四轮，训练 240000 步、4 个并行环境：

```bash
cd /home/climber/Climber_legged_rl
bash scripts/train_2080.sh 240000 4
```

该脚本先验证迁移来源、编译模型、生成姿态库并进行接触/数值检查，再启动正式训练，最后检查保存和重新加载。默认不传参数时只训练 8192 步。每次创建独立结果目录，父策略固定为云端第十三轮最佳策略。

如果希望从本次短测试的最终策略继续计数和训练，可使用原项目的 `--resume`：

```bash
cd /home/climber/Climber_legged_rl
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  /home/climber/.venvs/climber_rl_20261104/bin/python -u scripts/train.py \
  --backend cad-dynamics \
  --config configs/robot/cad_balance_estimator_round14.yaml \
  --device cpu --num-envs 4 --total-timesteps 240000 \
  --resume outputs/mujoco_runs/cad_balance_estimator_round14_2080_20261104_215513/final_policy.zip
```

这里的 `240000` 是额外请求训练的步数；PPO 按完整 rollout 收集，实际步数可能向上补齐。正式训练的预期收益需要更大样本评估，不能仅凭这次跑通测试判断短测试策略优于父策略。

## 迁移中处理的问题

云端生成的 XML 写死了 `/root/gpufree-data/Climber_legged_rl` 的绝对资源路径，已经逐字替换为目标仓库路径。190 个 XML 的原文件和修改前后哈希保存在 `outputs/relocation_2080_20261104/`；策略 ZIP、STL 网格与回放 NPZ 没有改写。

首次在新 CPU 上重建模型时，非唯一的闭链初始姿态求解使几个被动关节得到不同数值，严格的模型一致性检查正确地拒绝了续训。新脚本 `prepare_2080.py` 沿用云端检查点的原始模型及其已求解初始姿态，保留新 CPU 的求解结果供诊断。已验证除了求解初始姿态，重建候选 XML 的其他物理属性与迁移模型逐字一致。

当前用于训练的 XML 与父策略对应的 XML 完全相同；模型质量为 16.4634566 kg、六路执行器、六个闭链约束。资源路径迁移后的模型哈希为 `9306ef26d3c7b32bc174f1f9632b0914719e0299e989c804f13f271ef0abc085`。在目标机器上重新编译并验证了质量、约束误差、接地、力矩限幅、有限观测和奖励；重新生成的检查报告明确记录迁移来源，没有把历史评估当作新机器的测试结果。

回放数据仍为原始 `standing.npz`，SHA-256 为 `34007ad2a18607b4df28823c6665ee656aef65e126dde835a7865bad8c6b5874`。其 JSON 只更新了路径迁移后对应的模型哈希，并记录原始哈希与迁移清单。

后续应使用 `train_2080.sh` 保留检查点对应的模型。直接运行会再次求解 IK 的旧训练封装，可能再次因模型字节差异而被拦截。若主动修改物理模型或配置，应正常重新验证并明确处理策略迁移，而不是覆盖哈希或关闭校验。

## 结果边界

这次验证的是当前真实 CAD 路线的站立、起身和推扰训练流程，说明设备、环境、训练更新及检查点保存链路可用。气弹簧采用恒力近似，部分惯量、阻尼和电机控制包络仍是仿真假设。尚未证明行走、跳跃、越障等全部动作收敛，也不能直接把策略部署到实车。
