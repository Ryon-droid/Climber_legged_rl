## 为什么当前值得改变实验方向

以已完成的第 22 轮配对评估为基准：固定趴姿无扰起身并保持 20/20，随机站姿无扰 18/20，训练中反复出现的困难站姿仅 2/12；父策略、best、final 成功率相同。这个结果表明那一轮没有修复微小初态偏差下的站稳问题，并不能用固定起身成功代替站稳泛化。

样例 seed=99905 初态只有横滚约 -0.859°、俯仰约 +0.404°，无推扰也会画圈并触地。缺少历史、奖励尺度、控制响应、学习更新等都是待验证因素，源码对照不能证明其中任何一个是唯一原因。第 23 轮正在尝试冻结起身分支、单独学习站稳，应先按同种子评估其结果，不能提前认定有效。

当前 actor [128,64,32]、critic [256,128,64] 与复旦默认网络宽度相同。因此“单纯加大网络”目前优先级低于历史、控制核对和采样改进。

我们的位置奖励为 `10*exp(-(d/0.03)^2)`：d=3 cm 时约 3.68，d=8 cm 时仅约 0.0082。速度和航向也有较窄指数项。偏离后该项对不同恢复状态的奖励差异很小，值得测试宽/窄奖励组合；这不等于证明奖励就是画圈原因，也不意味着 PPO 对物理状态直接求导。

## 建议落地顺序

1. **先核对控制接口。** 在 MuJoCo 中分别检查正向轮速对应的真实行驶方向、左右差速对应的 yaw 正方向、IMU/重力坐标、腿关节方向，以及实际输出力矩/饱和比例。现有 CAD 坐标有自己的轴向定义，不能照搬对方左右符号或电机顺序。
2. **训练站稳历史观测对照。** 从站姿训练独立候选，先用 5 帧（100 Hz 下相邻帧间隔 10 ms，首尾跨度 40 ms）堆叠，保留现有起身策略。训练、评估、MuJoCo 回放和导出必须保持同一帧序、reset 填充、上一动作定义。历史输入改变网络维度，不能直接把旧 checkpoint 当成同结构续训；可设计复制/蒸馏初始化。
3. **单独测试奖励调整。** 在相同采样预算、相同种子下，对比原奖励与“宽尺度恢复项＋窄尺度精确项”，记录位置、速度、yaw、姿态、接触和饱和比例。不要一次同时改历史、控制限幅、奖励和随机化，否则难以判断收益来源。
4. **再处理实机可用的状态估计。** 当前 actor 使用仿真真实线速度和相对起点位移，实机必须有对应的轮速/IMU融合、里程计或外部定位。复旦历史速度估计可作为参考；仅估出速度并不能消除位置积分漂移。真值可以留给 critic 和监督训练，actor 应使用部署时可获得的数据。
5. **基础站稳通过后逐项加入随机化与碰撞。** 先小幅参数/观测扰动，再延迟，再增加外力冲量和偏心力矩。已有 2–15 N、0.05–0.1 s 推扰是约 0.1–1.5 N·s 的设定包络，不等同于比赛撞击。用 `J=∫Fdt`、作用点、机身角速度、恢复时间和允许位移描述难度，比只比较 N 更有意义。
6. **需要大幅提速时移植 GPU 后端。** 先建单机器人动力学对照，再做 64/256/1024…环境吞吐实测，按显存与接触/闭链稳定性选并行数。保留 MuJoCo 作交叉验证；不要假设另一物理引擎能直接等价运行现有六个闭链约束和气弹簧。

验收至少分开记录：随机站姿、未参与训练的扰动站姿、固定趴姿起身、起身后切换站稳、各方向受推。比较同一批种子、完整回合成功率和失败轨迹；困难训练种子只作为回归测试。现有 20 秒检查之后再补 60 秒持续保持，不能把重复固定初态解释成任意倒地自救。

## 不能直接照搬的细节

- 复旦六电机顺序是 `[左腿0,左腿1,左轮,右腿0,右腿1,右轮]`，我们是四腿后两轮；其训练参考角、plane MuJoCo 参考角和 PD 值也不完全一致。它们是不同模型/运行配置的代码，不能假定任意 checkpoint 与脚本匹配。
- 复旦控制周期由 0.005 s×2 得到 100 Hz；华工 V14 Flat 为 0.005 s×4 得到 50 Hz；我们为 0.001 s×10 得到 100 Hz。延迟帧数、历史帧数、gamma、推力持续步数不能脱离时间基准复制。
- 复旦默认配置 `push_robots=False`，`max_push_vel_xy=2.0` 也不是 2 N；启用后代码按质量、仿真步长换算短时外力。其终止条件和我们严格的 5 cm/5° 验收不同，不能直接比较 reward 或成功率。
- 华工普通 V14 `use_frame_stack=False, num_obs_hist=1`，DreamWaQ/HIM 是另设配置，不能把可选算法模块当成默认训练实际采用。其观测噪声旁有“暂时禁用”的注释，但配置仍给出噪声字典，基类也会据此创建噪声模型，应以所选配置和运行路径为准。
- 对方质量、尺寸、轮子力矩及气弹簧均不同，预训练权重不能直接控制我们的机器人。复旦 MuJoCo 示例轮子限幅为 5 N·m，我们当前为 2 N·m；不能据此提高我们的硬件限制。
- 华工 README 的 Sim2Real 部署/系统辨识仍在未完成路线图中；本次没有获得对方策略已在我们机器人上可靠工作的证据。
