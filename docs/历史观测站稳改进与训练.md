# 历史观测站稳改进与训练

2026-10-31。按同赛开源项目的历史信息、恢复奖励、随机化思路，在现有 MuJoCo/CAD 训练中实现；没有直接复制其机器人模型或预训练权重。

## 已实现

- **五帧历史**：每帧仍为原 36 维观测，总计 180 维，顺序由旧到新。控制周期 10 ms，首尾跨度 40 ms。reset 用最终初态重复填满；每次完整任务 step 只追加一次，避免起身环境的多层继承重复写入历史。训练、评估、回放统一通过 `make_mujoco_env` 创建。
- **兼容原策略的迁移**：支持普通 36 维模型和第 23 轮的双分支模型。起身分支冻结、只读取最新帧；站稳分支读取全部五帧。当前帧计算保留原网络，过去四帧通过零初始化投影接入第一层；critic 同样迁移。保存后可用普通 `PPO.load` 回放，支持再次 warm-start。
- **恢复奖励**：保留原精确站稳奖励，站稳阶段额外对位置、速度、航向和 yaw 速度采用 Huber 惩罚；偏离较大时仍有可区分的恢复信号。尺度分别为 10 cm、0.25 m/s、20°、0.5 rad/s，权重为 1、1、0.5、0.5。起身未完成时不施加这些新惩罚。最终 5 cm、姿态、速度和气弹簧验收不变。
- **可选随机化**：IMU/编码器噪声、回合内固定的动作延迟、左右轮接触摩擦系数变化、六电机力矩输出系数变化。独立随机流不消耗物理初态和推扰的随机数；显式 seed 可复现。物理判断和奖励使用真实状态。
- **控制诊断数据**：每步提供六电机输出力矩及各物理子步的限幅比例，评估汇总饱和比例，便于检查轮子是否持续打满。
- **回放/导出**：`play_getup.py` 接受配置对应的历史输入；TorchScript 导出记录帧序、reset 填充、上一指令语义和分支阈值，并执行数值一致性验证。

配置是分阶段的独立对照，默认 `cad_dynamics.yaml` 不开启这些新功能：

| 配置 | 历史 | 恢复奖励 | 随机化 |
| --- | --- | --- | --- |
| `configs/robot/cad_balance_single.yaml` | 单帧，对照基线 | 关 | 关 |
| `configs/robot/cad_balance_history.yaml` | 五帧 | 关 | 关 |
| `configs/robot/cad_balance_recovery.yaml` | 五帧 | 开 | 关 |
| `configs/robot/cad_balance_robust.yaml` | 五帧 | 开 | 开 |

新对照配置使用相同 PPO 超参数、随机种子及初态采样比例。原 36 维示范数据不包含可靠的连续历史和回合边界，因此四个配置都关闭旧示范回放，避免把独立样本重复五遍伪装成历史。它们也不启用绑定在旧示范回放中的逐更新起身保护门；冻结起身网络，并继续通过完整起身/站稳评估选择 best。冻结起身动作不保证切换到学习中的站稳分支后仍成功，必须看完整回合评估。

随机化版的初始范围是仿真实验参数，尚未通过硬件辨识：

| 参数 | 设置 |
| --- | --- |
| 角速度观测均匀噪声半宽 | 0.02 rad/s，之后乘原观测缩放 |
| 重力投影噪声半宽 | 0.005，无量纲 |
| 腿位置噪声半宽 | 0.002 rad |
| 六电机速度噪声半宽 | 0.1 rad/s |
| 动作延迟 | 每回合采样 0–2 个控制步，即 0–20 ms；FIFO 初值为零指令 |
| 轮接触摩擦乘数 | 每轮每回合独立 0.9–1.1，覆盖同一轮全部 CAD 接触网格；地面使用两轮乘数的较小值，避免 MuJoCo 默认取大值规则掩盖降摩擦。以原始系数重算，避免跨回合累乘 |
| 电机输出乘数 | 每电机每回合独立 0.95–1.05，随后仍按原力矩限幅和速度限制裁剪 |

## 训练和 MuJoCo 回放

建议先跑 `history`，需要严格比较时再用相同父模型跑 `single`。基础站稳改善后再跑 `recovery`，最后跑 `robust`。

```bash
cd /root/gpufree-data/Climber_legged_rl
/root/gpufree-data/.venvs/climber-validation/bin/python -u scripts/train_balance_history.py --variant history
```

启动脚本会生成模型、求解趴姿、执行 smoke，然后开始训练；已有其他训练进程时退出。默认从已评估的第 22 轮 best 迁移，保留原质量、六个闭链、155–220 mm 气弹簧限制、电机力矩限制及 2–15 N 推扰。它会打印 `RUN_DIRECTORY`，日志仍显示剩余时间。可自行指定已评估父模型：

```bash
/root/gpufree-data/.venvs/climber-validation/bin/python -u scripts/train_balance_history.py \
  --variant recovery --parent outputs/mujoco_runs/你的历史训练目录/best/best_model.zip
```

回放使用与所选训练匹配的配置，例如历史版：

```bash
/root/gpufree-data/.venvs/climber-validation/bin/python scripts/play_getup.py \
  --config configs/robot/cad_balance_history.yaml \
  --checkpoint outputs/mujoco_runs/你的历史训练目录/best/best_model.zip \
  --reset-mode folded --push-episode-probability 0 --loop
```

看困难站姿，将末行改为 `--reset-mode standing --seed 99905 --push-episode-probability 0 --loop`。正式评估应另选未用于训练和选模的新种子，并继续检查完整回合成功率及长时间保持。

```bash
/root/gpufree-data/.venvs/climber-validation/bin/python scripts/export.py \
  --checkpoint outputs/mujoco_runs/你的历史训练目录/best/best_model.zip \
  --output outputs/你的历史模型导出目录
```

历史模型不能直接接收原 36 维数组。导出的 `observations_in_order` 定义单帧布局，`observation_history` 定义如何拼成完整输入；每帧“上一动作”是上一条裁剪后的策略指令，加入执行延迟时也按此定义。

## 验证与范围

单元测试覆盖历史帧顺序和 reset、延迟时序、随机化复现、原普通/双分支策略迁移、起身分支冻结、历史权重更新、PPO 保存加载、TorchScript 数值一致性及恢复奖励。

真实 CAD 集成验证可重复运行：

```bash
/root/gpufree-data/.venvs/climber-validation/bin/python scripts/validate_history_balance.py
```

它对照迁移前后的完整无扰趴姿/站姿轨迹，再执行 4096 步短程 PPO，检查冻结参数、站稳参数更新和普通 PPO 加载。结果在 `outputs/cad_balance_history/validation/summary.json`；该 checkpoint 仅用于流程验证，不应当作正式训练成果。

本次验证已完成：两组回归测试分别通过 41 项和 47 项（后一组包含新增历史测试），最终历史测试 11 项再次通过。四个配置都通过模型生成、姿态校验及各 1000 步零动作/随机动作 smoke。迁移前后 seed=112000 的趴姿起身和站姿均完整运行 20 s，动作/qpos 最大误差为零；seed=99905 仍在 5.22 s 失败且轨迹误差为零，说明迁移保持了原行为，尚未修好该困难种子。短程 PPO 使用 2 环境、每环境 128 步 rollout，累计 4096 步；起身参数完全不变，站稳参数确有更新。验证模型已通过普通 PPO 重载和实际 TorchScript 导出，随机输入及真实仿真轨迹的导出误差均为零。正式长训练未启动。

本文记录第一步的历史站稳与可选恢复/随机化，当时 actor 仍使用仿真线速度。后续已补充 MuJoCo Warp GPU 物理和速度估计器，见 [GPU物理与速度估计器](GPU物理与速度估计器.md)，其中包含实测性能、闭环失败情况和新配置。原有四个对照配置的含义保持不变；跳跃、自救不在本次实现范围。
