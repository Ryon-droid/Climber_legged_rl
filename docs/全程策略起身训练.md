## 动作由谁决定

一个 36 输入、6 输出的 PPO actor 从第一个控制步开始输出四个腿关节动作和两个轮速动作。起身期间，腿目标为当前关节角加模型输出的增量；达到原有起身成功判定后，腿目标为站姿角加模型输出的残差。轮速全程直接来自同一个 actor。

运行时没有时间驱动的起身关节轨迹，没有额外平衡器，也没有忽略或替换模型动作的阶段。PD、电机速度限制和力矩限幅仍负责执行目标；这属于执行层。模型不直接输出 CAN 电流。

前0.6秒允许关节峰值40 N·m，随后未站稳时限20 N·m，站稳后恢复旧策略10 N·m控制限幅。起身期间使用Kp=80、Kd=2，达到站稳判定后使用Kp=20、Kd=1；这些设置只改变执行增益和上限，不生成动作或把机身搬到目标位置。没有按1.02秒切换到另一个控制器。0.6秒峰值窗口是仿真设置，硬件允许持续时间仍未实测。

质量约16.463457 kg、450 N/侧气弹簧、155–220 mm销轴中心距和六个闭链保持不变；仍按135 mm电机轴心中点至轮心侧视距离和原地站稳阈值验收。

## 训练后播放与评估

把下面 `你的运行目录` 替换成训练启动时打印的实际目录；best通常在首次5万步分组评估后产生。

```bash
MUJOCO_GL=glfw /root/gpufree-data/.venvs/climber-validation/bin/python scripts/play_getup.py \
  --config configs/robot/cad_getup_stand_round8_policy.yaml \
  --checkpoint outputs/mujoco_runs/你的运行目录/best/best_model.zip \
  --reset-mode folded --loop
```

```bash
/root/gpufree-data/.venvs/climber-validation/bin/python scripts/assess_getup_policy.py \
  --config configs/robot/cad_getup_stand_round8_policy.yaml \
  --checkpoint outputs/mujoco_runs/你的运行目录/best/best_model.zip \
  --output outputs/cad_getup_stand_round8_policy/assessment_best.json \
  --episodes 20 --seed 96000
```

best和final分别评估完整趴姿与站姿；先通过无推扰起身及原地保持，再增加推扰。起身成功仍须主体不触地、双轮接地、姿态/腿长/高度/位置/朝向/速度连续合格1秒，并保持到回合结束。
