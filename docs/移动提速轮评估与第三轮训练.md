## 下一轮修正

本轮PPO的价值损失很大。512步无更新梯度审计测得策略梯度范数约7.66，价值MSE梯度范数约968万；原`vf_coef=0.5`与全网络梯度裁剪共同作用，将裁剪系数压到约2.07e-7。这是策略更新受抑制的直接证据，但尚未证明它是移动失败的唯一原因。

第三轮显式使用`training.vf_coef: 0.0001`，并修正训练入口，使新训练和warm-start均实际读取此配置。未配置该项的历史warm-start继续继承原checkpoint值。配置值进行有限、非负校验；日志元数据记录实际使用的`effective_vf_coef`。

同初态种子、同父模型的两次真实512步更新对照：原权重策略参数变化L2约5.66e-6，新权重约2.79e-3，增加约493倍；KL约0.00252，低于0.01目标，参数有限，保存重载后动作完全一致。见[短跑报告](../outputs/cad_velocity_round3/update_validation.json)。这只验证更新链路，不能证明第三轮已学会移动。

第三轮配置：`configs/robot/cad_velocity_round3.yaml`。从本轮475000步best初始化；相同提速任务下，本轮选模存活12/21优于第0步父模型9/21，因此保留当前best作为起点。50万步、8环境、学习率3e-5、clip 0.1、target KL 0.01、3个epoch；腿探索标准差0.03、轮0.15。模型与本轮XML哈希完全相同；前后±0.30 m/s、转向±0.60 rad/s不变。没有增加力矩限幅、起身或推扰。正式日志保留`time/remaining`剩余时间。

验证：41项相关单元测试通过；新配置已重新生成模型，零动作/随机动作各1000步smoke通过；策略迁移校验、同种子512步更新对照和checkpoint重载通过。完整CLI另完成512步端到端短跑及最终21回合评估，run为`validation_velocity_round3_20261029_critic_weight`，状态completed，元数据确认`effective_vf_coef=0.0001`，日志显示`time/remaining`。该短跑移动仍0/18，仅验证训练入口，不视为第三轮正式训练或移动提升。

```bash
cd /root/gpufree-data/Climber_legged_rl

```

此命令循环测试前进及停车；按当前评估，可能在停车前约4秒主体触地。查看转向可用：
