# 训练提速验证

日期：2026-10-31，北京时间。正在运行的第17轮保留原进程，提速设置应用于下一次启动的第18轮。

## 已实施

- 4个常驻CPU评估进程并行运行独立回合。回合种子、顺序、20秒时长、无扰/受推分组、判定阈值和选模优先级不变；终评也使用相同并行路径。
- 对动作策略和配置、物理模型逐字节计算哈希；仅当确定性动作网络及观测特征参数完全相同，才复用上一次相同种子的评估结果。critic或探索标准差变化不影响确定性动作，因此不会触发无意义的重复评估；actor变化或配置/模型变化均重新评估。
- 复用记录标明evaluation_cache_hit和evaluation_source_timesteps，不能把复用当作新的独立测试证据。候选策略只要发生实际动作网络变化，完整评估照常运行。
- 起身更新保护仍每次执行，PPO更新、成功回放、8个采样环境、推扰难度和24万训练步数不变。没有通过减少回合、缩短仿真或放宽标准提速。

配置已启用training.evaluation_workers=4和training.cache_unchanged_policy_evaluation=true。旧配置默认串行、不复用，当前运行进程不受代码修改影响。

## 实测

同一第16轮best、同一100700起种子，四组（无扰站姿/起身、强制推扰站姿/起身）各4回合，完整20秒上限：

| 执行方式 | 耗时 | 相对串行 |
| --- | ---: | ---: |
| 串行 | 50.36秒 | 1.00倍 |
| 四进程首次启动 | 18.25秒 | 2.76倍 |
| 四进程常驻后 | 13.84秒 | 3.64倍 |

两次并行结果与串行逐回合、逐字段完全一致。时长受机器并行负载影响，这是评估环节基准，不是整轮训练提速承诺。重复策略真实缓存探测约0.039秒（含checkpoint保存与记录），无重复仿真。

报告：outputs/cad_getup_stand_round18_multidirection/evaluation_speed_benchmark.json。可用scripts/benchmark_training_evaluation.py复测。

41项相关测试通过，包括actor哈希不受critic影响、actor/配置变化强制重评、分片结果正确合并与顺序、原有选模和起身保护。模型重建与1000步smoke通过，XML仍与成功父模型一致。8环境4096步完整runner验证正常完成采样和终评，保存策略可由普通PPO独立加载、参数有限；短跑不证明第18轮已学会强推扰。证据在speed_validation_summary.json和outputs/mujoco_runs/validation_getup_round18_20261031_parallel。

## 4090与后续命令

本项目目前使用CPU MuJoCo动力学、CPU小型MLP策略。之前实测4090利用率约0–3%；仅把device改为cuda不会把MuJoCo物理仿真搬到GPU，也不能据此承诺提速。本次针对占时较多的串行评估优化，继续使用CPU策略。要大量使用4090，需要另行实现并验证GPU物理后端及闭链/气弹簧等动力学等价性。

当前第17轮完成后，原命令即可使用提速配置：

    cd /root/gpufree-data/Climber_legged_rl
    bash scripts/train_getup_round18.sh

没有自动停止第17轮，也没有自动启动正式第18轮。
